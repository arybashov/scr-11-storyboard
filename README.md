# Подземный переход

Рабочая доска фильма SCR-11: один эпизод с такси, 11 событий, 12 монтажных кадров и аниматик на 19,3 секунды. Сценарий пилота, раскадровка, персонажи и ассеты с общей загрузкой изображений.

Страница: https://arybashov.github.io/scr-11-storyboard/

## Работа команды

1. Откройте «Раскадровка» и выберите эпизод.
2. Нажмите «Войти для загрузки», укажите имя и код проекта, полученный у владельца.
3. Перетащите JPG, PNG или WebP на карточку либо нажмите «Загрузить». Можно выбрать несколько файлов и добавить комментарий.
4. Нажмите изображение, чтобы просмотреть версии, автора, дату и открыть оригинал. Авторизованный участник может выбрать основной вариант.
5. Внизу раскадровки находится таймлайн. «Смотреть» открывает аниматик из основных изображений с заданными длительностями. Доступны пауза, перемотка и переход по кадрам; пробел управляет воспроизведением, стрелки переключают планы. Пока без звука и без экспорта видеофайла.

Изображения доступны по ссылке, как и сценарий; общий код защищает изменение доски. Имя — подпись участника, не отдельная проверенная учётная запись. Галерея обновляется каждые 15 секунд. Оригиналы сохраняются без изменения, для просмотра создаются уменьшенные WebP. Лимит файла — 15 МБ и 20 мегапикселей. Анимированные изображения не поддерживаются. Общий лимит хранилища — 1 ГБ.

## Разработка и публикация

Статический клиент не требует сборки. Для локального просмотра: `python -m http.server 8871 --bind 127.0.0.1` из корня. GitHub Actions публикует только клиентские файлы в Pages при push в main. Секретов в клиенте нет.

API: Node.js 20.9+, `server/server.mjs`. Установка: `npm ci` в `server/`, проверка: `npm test`. `config.js` содержит публичный адрес API. Весь трафик публикации использует HTTPS.

На существующем сервере YUI выделены отдельный пользователь и systemd-сервис `kino-board`, каталог кода `/opt/kino-board`, постоянное хранилище `/var/lib/kino-board`, закрытый файл конфигурации `/etc/kino-board/environment`. API слушает только `127.0.0.1:8792`; nginx публикует его под `/kino-api/`. Игровые процессы не перезапускаются. Наличие сервера не подтверждает его географию или провайдера.

`scripts/deploy_server.py` развёртывает API по существующему SSH-доступу и сохраняет код команды в файл вне репозитория. Он проверяет текущую структуру nginx и сохраняет резервную копию перед добавлением отдельного include. При повторном деплое сохраняет существующие секреты и загруженные изображения. Обновление API выполняется отдельно от публикации Pages.

Обязательные переменные API: `DATA_DIR`, `TEAM_ACCESS_CODE` (12+ символов), `SESSION_SECRET` (32+ символа). Необязательные: `PORT`, `ALLOWED_ORIGINS` (точные origin через запятую), `MAX_STORAGE_BYTES`.

Для резервной копии остановить только `kino-board`, скопировать весь `/var/lib/kino-board` вместе с `index.json` и `media/`, запустить сервис. Копия должна храниться отдельно от сервера. Автоматическое внешнее резервное копирование пока не настроено.

## Персонажи и ассеты
Вкладка `#assets` содержит стартовые карточки пилота, категории и ссылки на кадры. Референсы сохраняются на том же сервере отдельно от кадров (`assets` в индексе). Загрузка и выбор основного референса требуют существующего кода команды; просмотр открыт. Первый референс становится основным автоматически. Дизайн пока не утверждён.
Данные карточек: `assets.js`; при добавлении карточки её идентификатор нужно включить в `validAssets` сервера. API: `POST /assets/:id/images`, `PATCH /assets/:id/current`. Тест проверяет разграничение ассетов и кадров и сохранность после перезапуска.

## Редакция пилота — 05.11.2026
На сайте оставлен только эпизод с такси по новой авторской последовательности: 11 событий, 11 монтажных кадров, 20 секунд по уточнению автора. Сильный дождь начинается до первого кадра; телефон поднят до гудка; мусоровоз проходит после отскока. Финал — крик до конца дыхания. Упоминания самосвала и мусоровоза сведены к одной машине — мусоровозу.
Вкладка сценария и текст под кадрами берутся из `PILOT_BEATS` / `EPISODES` в `episodes.js`. Исходный DOCX сохранён отдельно. Схемы новой редакции — `pilot-sketches.js`. Библиотека содержит пять ассетов текущего эпизода. Старые серверные версии не удаляются; предыдущая схема T02 доступна в истории.

Хронометраж уточнён автором: ровно 20 секунд. T01–T12 — 12 секунд, T13–T15 — 8 секунд. Дробные длительности сохраняются в таймлайне и плеере.

Составные кадры: T01 включает фазы прежних T01/T02 (2,4 с); T05 — T05/T06 (2,2 с). На таймлайне каждый занимает один сегмент; в плеере меняются опорные фазы внутри этого сегмента. Схемы фаз не являются готовой анимацией движения камеры. Загрузка и версии сохраняются отдельно для каждой фазы под прежними серверными ID. Общая длительность — 20 с.

T13–T15 объединены в T13 (8 с): T13а — крик, T13б — мокрое лицо, T13в — последний выдох. В строке три миниатюры, на таймлайне один сегмент; смена крупности описана как непрерывное движение камеры. Всего 11 монтажных кадров и 20 секунд. Версии фаз сохраняют серверные ID T13/T14/T15.

Актуальное перераспределение: до финального крика 16 с, объединённый T13 — 4 с (1,5 + 0,8 + 1,7). T01 — 3 с; T03 — 1,1; T04 — 2; T05 — 2,2; T07 — 2; T08 — 0,6; T09 — 0,8; T10 — 1,1; T11 — 1,7; T12 — 1,5. Итого 20 с. Эти значения заменяют прежний хронометраж.

Уточнение автора: T04 — 1,5 с; освободившиеся 0,5 с перенесены в T07 (теперь 2,5 с). Общий хронометраж остаётся 20 с; финал 4 с.

Уточнение по T05: 2 с (0,6 с взгляд + 1,4 с выход на дорогу). T03 — 1,3 с; перенесены 0,2 с для сохранения общего хронометража 20 с. T04 остаётся 1,5 с, финал — 4 с.

Текущий принцип: подбирать длительности по ритму, не компенсировать сокращения ради 20 с. Компенсации отменены: T03 — 1,1 с, T07 — 2 с. T04 — 1,5 с; T05 — 2 с; T13 — 4 с. Актуальная сумма — 19,3 с.

Последний план отделён: T13 — крик и мокрое лицо, две фазы / 2,3 с; T15 — сгибание на последнем выдохе, самостоятельный кадр / 1,7 с. Всего 12 монтажных кадров, 19,3 с.
